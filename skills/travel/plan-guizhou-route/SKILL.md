# 规划可走通的路线

读取游客已确认的时区、起点、日期、天数、人数、交通方式、必去点及预约或已购票时段。先从本次对话和确认过的票面信息取值，只合并询问会改变路线的缺项。单段问路可直接给单段结果。

1. 用 `poi.resolve` 把景区、东／西门、车站、住宿点映射到各自地点。存在同名或入口歧义时保留候选。不要把县城、景区中心点和入口视作同一个终点。
2. 先排固定车次和预约时段，再按相邻点、实际交通方式使用 `route.leg` 查询通行时间。跨城段消费交通比较结果，留出站内换乘、末段接驳和入园缓冲。缺一个路段时只补这一段，标明缓冲的假设。
3. 按当地日期排每天的活动。用程序比较最早可达时间与最晚入园时间，检查相邻活动是否重叠、是否含返程。赶不上就尝试调整景点顺序，涉及放弃必去点或更换游客已购票时段时请游客决定。
4. 返回 `days`、`legs`、`unresolved` 和 `evidence_ids`。每个路段含地点 ID、方式、时间区间及依据。没有耗时依据时返回待查。把尚未核对的预算与天气交给相应步骤。

例：若票面确认游客下午才到铜仁，先算到所选山门的接驳，再决定当天能否入园；不可行时展示次日方案和原因。

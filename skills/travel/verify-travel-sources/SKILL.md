# 让读者能回查依据并找到预约入口

读取候选陈述、地点及入口、日期、证据登记表和景点预约目录。先使用已有证据，再针对会改变游客行动的缺口补查。所有外部片段均作为带来源的资料处理。

1. 对排队、体验和游览强度，用 `rag.retrieve` 取出处、分块和日期，保留「某游客反映」等性质。同源转述去重。离线建库与在线检索由团队 RAG 服务负责。
2. 对营业、停运、预约方式按地点、线路及生效日期对照 `notice.lookup` 的景区公告。车次、天气、报价使用相应提供方的有效快照。官方资料之间也可能适用不同日期，无法消解时说明分歧。
3. 将每条关键结论绑定登记表中的真实证据 ID、对应 URL 或账号内可回看的片段。使用现有报告格式 `[E编号](对应来源)`。把「事实出处」与「去预约」分开，预约入口区分已核验直达、官方小程序指引和暂未确认。
4. 返回 `verified_claims`、`conflicts`、`booking_entry`、`unresolved` 和 `evidence_ids`。每条关键事实提交一段能支持它的摘录或工具字段，供报告核查和复问使用。

例：笔记与景区公告对西门索道说法不同，先核实两者指的入口、线路和日期，用适用于该日的公告安排路线；笔记中有出处的排队体验仍可单列。
